# طراحی UX برند

## Mission
Deliver a traceable, evidence-based result for the طراحی UX برند domain while following the project's architecture, ADRs, API contracts and Definition of Done.

## When to use
Use when designing or reviewing public brand, product education, storefront and B2B experiences.
## Required workflow
1. Define brand promise, audience, intent and trust signals.
2. Design user journey first, then information hierarchy, then layout and components.
3. Use reference sites for interaction principles only; create original brand expression.
4. Design desktop and mobile states including loading, empty, error, unavailable, success and validation.
5. Product page must clarify purpose, variants, contents, usage, safety/claims approval, price availability, delivery, FAQ and support.
6. B2B pages must distinguish application, verification, negotiated price, MOQ and quote status.
7. Include accessibility, RTL and localization from the first frame.
## Output
Journey map, page anatomy, wireframes, responsive behavior, copy intent and usability test plan.
## Guardrails
Do not make unapproved efficacy/medical claims or copy source-site artwork/text.

## Repository context to read first
- `README_FA.md` and the relevant `docs/` specifications.
- Relevant ADR and ownership boundaries.
- Current implementation, tests and lockfile; code is the current implementation truth.
- Never assume planned documents reflect what has already shipped.

## Handoff format
- Objective and scope.
- Files/modules changed or inspected.
- Decisions and assumptions.
- Tests/checks run with exact result.
- Unverified items, risks and follow-up.
