# چارچوب جامع مانیتورینگ، تله‌متری و مشاهده‌پذیری (Monitoring & Observability)

این مستند معماری، پروب‌های سلامت، استانداردهای توافق‌نامه سطح خدمات (SLA/SLO)، سنجه‌های تله‌متری و ابزارهای پایش پلتفرم **DERMAVIA Brand Commerce** را تعیین می‌کند (مرجع بند GAP-033 و وظیفه S-019).

---

## ۱. لایه‌های چهارگانه مشاهده‌پذیری (Observability Pillars)

پلتفرم بر پایه چهار رکن اصلی مانیتورینگ پیاده‌سازی شده است:

```
+-------------------------------------------------------------------------+
|                       1. پایش ترکیبی (Synthetic Probes)                 |
|   scripts/health-monitor.mjs  -> بررسی دوره‌ای سنجه‌های در دسترس‌پذیری     |
+-------------------------------------------------------------------------+
                                    |
+-------------------------------------------------------------------------+
|                  2. پروب‌های سلامت کانتینر (Health Probes)              |
|   /api/v1/health/liveness (حیات) | /api/v1/health/readiness (آمادگی ترافیک)  |
+-------------------------------------------------------------------------+
                                    |
+-------------------------------------------------------------------------+
|                  3. تله‌متری مصرف منابع (System Telemetry)              |
|   /api/v1/health/telemetry  -> حافظه RSS، Heap، آپ‌تایم و وضعیت اتصال DB  |
+-------------------------------------------------------------------------+
                                    |
+-------------------------------------------------------------------------+
|                 4. رهگیری درخواست‌ها (Distributed Request Tracing)       |
|   هدر X-Request-Id + لاگر ساخت‌یافته HTTP + لاگ ممیزی تغییرناپذیر        |
+-------------------------------------------------------------------------+
```

## ۲. مشخصات اندپوینت‌های سلامت و تله‌متری

| اندپوینت | روش | نوع دسترسی | عملکرد و هدف | کد پاسخ سالم |
| :--- | :---: | :---: | :--- | :---: |
| `/api/v1/health` | `GET` | عمومی | بررسی عمومی سلامت سرویس و دیتابیس (سازگاری به عقب) | `200 OK` |
| `/api/v1/health/liveness` | `GET` | عمومی | پروب حیات کانتینر؛ تایید پاسخگویی پروسه Node.js | `200 OK` |
| `/api/v1/health/readiness` | `GET` | عمومی | پروب آمادگی؛ اعتبارسنجی اتصال به دیتابیس (پاسخ ۵۰۳ در صورت قطع) | `200 OK` / `503` |
| `/api/v1/health/telemetry` | `GET` | عمومی | سنجه‌های تله‌متری: حافظه RSS، Heap، نسخه نود، محیط، آپ‌تایم | `200 OK` |
| `/api/v1/admin/audit-logs` | `GET` | اپراتور (`x-admin-key`) | مشاهده لاگ‌های ممیزی تغییرناپذیر عملیات مدیریتی | `200 OK` |

| :--- | :---: | :---: | :---: |

| **نرخ خطای سرور (۵xx Error Rate)** | **کمتر از ۰.۰۵٪** | **کمتر از ۰.۵٪** | ساعتی |

## ۵. داشبورد تله‌متری در کنسول اپراتور (`/admin`)

اپراتورها و تیم SRE می‌توانند با ورود به کنسول `/admin` از تب‌های اختصاصی زیر وضعیت لحظه‌ای را نظارت کنند:
1. **تب تله‌متری و سلامت:**
   - نمایش کارت‌های زنده وضعیت API، پایگاه‌داده، مصرف RAM پروسه به مگابایت، و مدت آپ‌تایم.
   - دکمه بازخوانی زنده جهت دریافت تازه‌ترین مقادیر مصرف حافظه.
2. **تب لاگ‌های ممیزی امنیتی:**
   - جدول زمانی تغییرناپذیر از کلیه کنش‌های اپراتورها همراه با برچسب‌های رنگی، زمان وقوع دقیق و جزئیات پارامترهای ارسالی.

## ۶. ماتریس هشدارهای بحران و تریاژ (Alert Escalation)

| رخداد | سطح شدت | شرط فعال‌سازی | کانال اعلام | اقدام اولیه طبق ران‌بوک |
| :--- | :---: | :---: | :---: | :--- |
| **شکست پروب Readiness** | **SEV-1** | ۳ شکست متوالی (DB Down) | پیامک فوری + PagerDuty | بررسی اتصال PostgreSQL و ران‌بوک RB-01 |
| **مصرف حافظه بحرانی** | **SEV-2** | RSS > 500MB یا Heap > 85% | هشدار اسلک / ایمیل SRE | لاگ Heapdump و بررسی نشت حافظه |
| **افزایش تاخیر p95** | **SEV-2** | Latency > 400ms در ۵ دقیقه | ایمیل تیم بک‌اند | بررسی تراکنش‌های همزمان انبار و لاگ کوئری‌های کند |
| **خطای مسیرهای غیرحیاتی** | **SEV-3** | خطای تک‌پروب استورفرانت | ثبت در لاگ‌های ممیزی | بررسی و رفع در چرخه نگهداری معمول |
